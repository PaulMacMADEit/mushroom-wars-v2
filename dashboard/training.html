What the training loop actually does

1. The PPO cycle

Each training run is a loop of Proximal Policy Optimization updates until a wall-clock budget runs out. One update:

  • Rollout — 32 envs run in parallel (one subprocess each). Each env plays a game where P1 is the current agent, P2 is the opponent (see below). We collect rollout_steps (default 128) action-decisions per env, → 32 × 128 = 4096 transitions per batch.
  • Update — 4 epochs over the batch in minibatches of 512. Policy-gradient with clipped ratio + value-head regression + entropy bonus.
  • Repeat — until budget (15 min, 30 min, 3 h etc.) expires.

2. Who you're playing (and why it changes over time)

Each env picks its P2 opponent from a self-play pool:

  • Before any snapshot exists → random_legal (uniform over the action mask). This is the "absolute" baseline on the Leaderboard too.
  • Every snapshot_every updates (default 10), a frozen copy of the current weights is added to the pool. Pool caps at pool_max_size=20 — oldest get evicted.
  • After the first snapshot: each env draws an opponent with latest_bias=0.8 probability of the newest snapshot, and 20% chance of an older one (uniform over the rest).

Effect: you spend most of your training playing slightly older copies of yourself, occasionally revisiting older versions to avoid forgetting how to beat them. The agent is mirrored (P1 ↔ P2 ownership swapped) before encoding so a P1-trained net can act as P2.

3. Post-training evaluation

When a run finishes, the worker auto-admits it into the ranking pool:

  • 10 games against each of the current top-5 Elo runs (50 games total).
  • 20 games against the fixed random_legal baseline — this is the "vs random" column on the leaderboard.

Results feed into per-game Elo updates (K=32, init=1200), so the leaderboard doesn't inflate as the meta gets stronger. Every game played is a row in games; the per-match summary goes in matches.summary.

4. Maps

  • random_8_12 — 180°-symmetric random geometry, 8-12 buildings per episode. Fresh map every reset. Current production baseline.
  • random_N_M — any N-M range (e.g. 8-24, 8-32) for breadth sweeps.
  • asym_N_M — asymmetric variant for OOD stress testing.
  • crossroads_6 — fixed handmade level (not used for current training).

5. Reward signal (already shaped, not sparse)

+0.1
for each building captured (neutral or enemy)
−0.1
for each of yours lost to an enemy (not neutral-to-enemy)
+1.0
on win (enemy base destroyed / all enemy buildings gone)
−1.0
on lose
0.0
on draw (tick cap hit)

Dense (capture/loss) + sparse (terminal). Credit assignment should be healthy — if the agent still makes bad decisions it's more likely a capacity / budget issue than a reward-signal issue.
